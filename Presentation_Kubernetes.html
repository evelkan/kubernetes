Volumes persistants

PV nginx-pv — 1Gi

Nginx

Monté sur /usr/share/nginx/html
storageClassName: manual

PV mariadb-pv — 5Gi

MariaDB

Monté sur /var/lib/mysql
storageClassName: manual

# Résultat kubectl get pv / pvc NAME STATUS STORAGECLASS mariadb-pv Bound manual nginx-pv Bound manual NAME VOLUME CAPACITY mariadb-pvc mariadb-pv 5Gi nginx-pvc nginx-pv 1Gi

Problème rencontré

K3S inclut un provisionneur local-path qui intercepte les PVC sans storageClassName. Solution : ajouter storageClassName: manual dans PV et PVC.

Principe du moindre privilège

Helm — Package Manager

Sans Helm
  • 3-5 fichiers YAML par application
  • Mise à jour manuelle de chaque fichier
  • Rollback complexe et risqué
  • Pas d'historique des versions
Avec Helm
  • 1 commande pour tout déployer
  • Historique automatique (REVISION)
  • Rollback en 1 commande
  • Charts réutilisables et partageables
# Installer nginx en 1 commande helm install mon-nginx bitnami/nginx # Personnaliser helm install nginx-custom bitnami/nginx \ -f values-nginx.yaml # Historique helm history nginx-custom REVISION STATUS 1 superseded ← install 2 superseded ← upgrade 3 deployed ← actuel # Rollback helm rollback nginx-custom 1

Quand utiliser quoi ?

🐳
Docker

Dev local / serveur unique

  • Développement sur sa machine
  • Petite app sur 1 VPS
  • Débutant en conteneurs
  • Pas besoin de HA

Ex: Blog perso, app de test

Docker Swarm

Cluster simple / petite équipe

  • Déjà sur Docker Compose
  • 2-3 serveurs max
  • App simple sans microservices
  • Ressources formation limitées

Ex: PME 2-3 serveurs

K3S / Kubernetes

Production / microservices

  • Besoin RBAC, Helm, PV/PVC
  • IoT / Edge computing
  • Lab de formation (ce projet !)
  • Montée en charge prévue
